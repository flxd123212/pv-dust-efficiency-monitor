# 光伏监测与手机控制台 V3

现有 STM32F407 工程的增强版。复用原有设备，并支持接入用户已有的四针雨滴模块，不要求新增其他硬件。

**传感器修复：PB1 是电位器电压，不是温度。新版改读 PB6/PB7 上的 SHT20 环境温度；
扩展板无应答、CRC 错误或超时，测量显示 `--`。旧版本读数不再作为有效测量展示。**
详细接线、原因与实机检查见 `docs/sensor-audit.md`。

## 当前方案

```text
现有开发板 -- 原有 ST-Link 排线 / USB 虚拟串口 -- 电脑网关 -- 手机浏览器
                                       |
                                    MQTT/TLS
                                       |
                                云服务器 + HTTPS 控制台
```

需要电脑作为网关并保持运行。手机和电脑在同一局域网时可直接使用；
OneNET 方案可直接使用官方 MQTT 服务和物模型可视化，不必自建云服务器。
自行部署外网控制台的方案仍需要云服务和 MQTT 账号。
**没有自动刷写板载 ESP-12F，没有声称开发板可以脱离电脑独立联网。**

## 已实现

- PC8 硬件 PWM，20 ms 周期，0..90° 限幅、平滑调整，开机目标 0° 收起。
- 设备本地触摸、按键与手机远控共用控制校验；设备 ACK 对账，不以网页输入值冒充设备状态。
- 清扫定时停止、雨天/温度/ADC 异常保护、自动清扫冷却间隔、停止动作和报警静音。
- 电流按 0.1Ω 分流电阻、101 倍放大器换算；SHT20 温度应答/CRC/超时校验、每通道有效性与清洁电流基准标定。
- 两个独立 Flash 扇区保存参数，CRC 校验、最后写入提交标记、断电后使用最后有效记录。
- 上电始终停止清扫、进入手动模式，不自动恢复电机。
- 本地雨天联动：有雨转到 90° 挡雨并停止清扫；持续无雨 10 秒后转回 0°，不自动恢复清扫。
- 扩展板 PB4 人体红外活动报警、PC4/LD1 联动；电脑和手机提供独立“人体报警”维修开关，不影响雨天等保护。
- 下载器虚拟串口走 USART6 PG14/PG9；保留 USART1/3 备用链路，均为实际 115200 波特率。
- 手机响应式工作台、实时推送、趋势、CSV、操作审计、串口选择、密码登录和断网锁定。
- 本地网关/云端两种服务角色、MQTT/TLS 双向转发、断线重连、陈旧命令拒绝。

## 本机与手机使用

1. 使用 Keil 打开 `MDK-ARM/pv_ui.uvprojx`，编译并手动下载 `MDK-ARM/pv_ui/pv_ui.hex`。
   本次开发不会自动烧录设备。
2. 舵机信号继续接 PC8，其余接线不变。资料所示底板的 PC8 同时连接 KEY2，**使用舵机时不要按 KEY2**。
   四针雨滴模块按丝印连接：VCC -> 3.3V（模块需支持此供电），GND -> GND，DO -> PA4，AO 不接。
   原底板 PA1 连接五向按键运放输出，不再配置或读取为雨滴输入。接线前断电，不得输入 5V 电平。
3. **本次实物使用原有下载器和 10 针排线，不切换跳线、不增加模块。**
   下载通过 SWD；同一排线的 TX/RX 同时提供 USART6 通信：PG14 TX、PG9 RX，115200/8/N/1。
   电脑选择 `STMicroelectronics STLink Virtual COM Port`，本机当前是 **COM6**；不要选另一个 CH340 COM5。
   教程 PDF 第 223～224 页（印刷页码 209～210）及核心板原理图明确给出该接法。
   原固件漏配 USART6，需要重新烧录修复后的 HEX；只有串口打开、但未收到有效数据时仍显示设备离线。
   备用方案仅适用于确认接线匹配的其他板型：USART1 PA9/PA10；USART3 PB10/PB11 经 CH340。
   FS-STM32db-v3.2 底板的 S2/S3 切换说明只适用于使用该底板 CH340 的情况，不是本机必要步骤。
4. 运行 `tools/start-platform.ps1`，或在 `platform` 目录执行：

   ```powershell
   npm ci
   npm run build
   npm start
   ```

5. 电脑访问 `http://localhost:8787`。初始随机密码位于 `platform/data/admin.secret`，也可以设置 `PV_PASSWORD`。
   在“设备设置”选择板子的串口，等待真实遥测后控制自动解锁。没有设备时不会填充模拟数据。
6. 手机与电脑连接同一个 Wi-Fi，访问启动日志列出的 `http://电脑局域网IP:8787`。
   如无法访问，检查 Windows 防火墙是否允许 Node.js 的专用网络访问，以及路由器是否开启客户端隔离。
   不需要另买串口模块或 Wi-Fi 模块。
7. 也可在电脑上打开 `http://localhost:8787`，登录后点击右上角二维码图标“手机访问二维码”。
   默认选择当前 Wi-Fi 地址，可切换其他有效网卡；弹窗打开期间每 15 秒刷新地址，并支持复制地址、下载二维码。
   二维码在本机生成，只编码网址，不包含登录密码、会话或 OneNET 密钥；手机扫码后仍需正常登录。
   IP 改变后应扫描电脑上更新的二维码，先前下载或截图保存的二维码不会自行改变。
   **二维码只免去手输 IP，不能绕过校园网/访客网的设备隔离，也不提供固定公网入口。**
   若扫码后连接超时，需要使用允许设备互通的网络、个人热点，或另行配置私有组网。

端口占用时设置 `$env:PV_PORT='8788'` 后再启动。网页服务默认监听 `0.0.0.0`，不要把此 HTTP 端口直接映射到公网。

## 设备功能

- KEY1 / USER：切换页；KEY3 短按：目标角度增加 5°；KEY3 长按一秒：停止动作并返回手动模式。
- 触摸控制页：清扫开关、升高、降低、停止、手动/自动模式；停止锁定后原停止按钮和底部模式按钮均变为 RESUME，可再次点击恢复。
- 扩展板人体红外使用 PB4/RDA226，不需另接线。接入后预热 60 秒，活动触发报警，连续未检测到活动 5 秒后清除人体报警。
  人体活动只触发报警，不停止清扫、不改变模式或舵机角度；它不是距离或静止人数测量，未触发不代表绝对无人。
  电脑和手机首页“扩展板状态”下的“人体报警”开关可维修关闭；关闭后仍显示活动，但不再因人体触发蜂鸣器和 LD1。
  雨天、过温、积灰和采样异常报警仍保留。界面显示“维修关闭”，LCD 标记 ALARM OFF；开关以实际固件上报为准。
  此开关不写 Flash，重新上电默认开启。旧固件、离线或命令等待期间禁用开关；新增功能需烧录本次 HEX。
  LD1 使用 PC4：报警快闪、清扫常亮、停止锁定慢闪、空闲熄灭。静音 60 秒不关闭 LD1 或活动显示。
- 四针热敏模块：VCC→3.3V、GND→GND、AO→PA5/ADC1_IN5，DO不用于测温。实物照片中原先误接了DO，AO是最下面单独露出的针脚。
  固件按可配置的10kΩ、B3950、上拉10kΩ模型换算20～80℃，明确标为“估算”，无效/越界/过期显示`--`。
  型号、B值和分压接法尚未实物校准；不能把典型参数当作已确认精度。不要直接接5V AO，探头需实际接触面板才有板温意义。
  LCD、电脑和手机分开显示环境温度与板面温度；`panelTemp`仍是SHT20环境温度，新`surfaceTemp`为NTC估算值。
  OneNET新增只读`personDetected`和`surfaceTemp`，需先在产品物模型创建并发布，定义见`docs/onenet.md`。
  换算、过期和校准边界见`docs/ntc-temperature.md`。
- 自动清扫默认关闭。核实真实电流回路和现有雨滴输入，完成清洁基准标定并保存后，才允许开启。
- 扩展板自身没有雨滴传感器。当前固件启用外接模块 PA4/DO：低电平按有雨保护，高电平持续 500 ms 才判无雨。
  PA4 使用内部下拉，DO 悬空时按有雨保护；这不能区分真实下雨与断线，不是独立断线检测。
  雨滴数据尚未就绪或超过 1 秒未采样时标记未知并禁止清扫；不会因插入扩展板就认为无雨。
  有雨或 DO 悬空时停清扫、退出自动清扫并转向 90°；确认无雨连续 10 秒后转回 0°。
  确认期间再次有雨、未知或数据过期都会重新计时；保护运动中雨滴失效则保持当前角度。
  该联动在手动模式也生效，不依赖电脑、手机或云端；雨后不恢复清扫，需明确重新启用。
- 只有工作电流不少于 50 mA、估计损失持续超阈值 30 秒、无雨、未过温且冷却时间结束时才会自动清扫。
- 单次清扫可设 3..30 秒，默认 10 秒；自动清扫间隔 60..3600 秒，默认 900 秒。
- “停止所有动作”停止 PC6 清扫输出、退出自动模式，并保持当前已发出的舵机角度。
  停止锁定不会被雨天联动或重连解除；手机点击“恢复联动”或 LCD 的 RESUME 后才恢复天气联动，清扫仍关闭。
  它不是具有独立硬件认证的急停。
- 手机显示的雨天联动状态来自固件遥测，旧固件显示“固件待升级”。仅更新网页不能改变板上动作，需烧录新 HEX。
  电脑和手机共用响应式控制页，提供“0° 收起”“90° 挡雨”快捷操作、停止和恢复联动。
  舵机区域同时显示指令角度、目标角度、递增/递减/保持/停止状态，以及雨后确认倒计时和锁定原因。
  雨天禁止收起；雨后收起中、停止锁定和雨滴失效时限制相应控制。离线显示最后上报并锁定控制，动作未确认不假显示成功。
  “清扫模式”只管理清扫，不是关闭雨天安全联动的开关。操作记录区分收起、挡雨及设备拒绝结果。
  行程与连杆需实机确认，烧录/复位前清空运动范围；舵机无编码器，显示角度是 PWM 指令而非轴角实测。
  联动契约和验收范围见 `docs/rain-automation.md`。积灰基准需在相同角度、光照和负载条件下标定。
- 参数先“应用”，再“写入设备”；正在清扫时拒绝写 Flash。Flash 扇区 10/11 已由专用链接脚本预留。
  V3 修正了电流比例，旧版基准不再加载，需要重新标定并保存。
  Keil 的整片擦除会清除保存参数；普通下载应只擦除程序使用的扇区。

## 数据边界

没有增加光照、面板电压或角度反馈传感器，因此：

- `dustLevel` 是相对于标定电流的损失估计，不是颗粒浓度、实测积灰量或准确发电效率。
  云层、阴影、负载变化也会导致电流下降。电流不足时显示待判断，不据此启动清扫。
- 环境温度来自 SHT20；板面温度来自 PA5/NTC 模型估算，参数及探头贴合未经实物校准。两者分开显示、上传，不相互代填；PB1只保留为电位器电压诊断。
- 电流是扩展板采样回路的换算值；未核实其已串入真实光伏电流回路前，不能声称是实际发电电流。
- 模拟引脚悬空仍有原始 ADC 数字。新版以 SHT20 应答/CRC 门控整板测量有效性，未接整板不发布有效电流；
  单独拔掉模拟信号线而数字传感器仍在线的情况，不能仅靠软件百分之百识别。
- `tiltAngle` 是 PWM 指令角度，并非编码器测量的实际轴角度。机械零点与脉宽范围仍需按现有机构校准。
- 不显示没有真实采样依据的瓦数、累计电量或辐照强度。人体活动来自 PB4 实际电平，未连接、预热和失效与无活动明确区分。

历史最多展示/导出 900 个时间桶，底层保存真实上报记录；遥测保留 30 天，审计保留 90 天。
protocol=2 旧记录保留用于审计，但展示及导出屏蔽其错误映射的测量字段，不伪造修正后的历史值。
断连保留最后上报值并明确标记离线，所有远程动作按钮锁定。模拟模式使用独立数据库且始终有醒目标识。

## 上云

OneNET 方案见 `docs/onenet.md`，直接复用本机串口网关，不增加硬件、不需要自建 MQTT 服务器。
使用私有 platform/.env 配置产品/设备信息；程序按官方规则生成并自动续签 Token。
已实测通过 OneNET 官方 TLS 与设备 Token 鉴权，不代表开发板已在线或五项传感器均有有效数据。
只有平台回复 code=200 才显示上报已确认；失效温度、未接雨滴、未标定积灰不会填零上传。
费用和配额以 OneNET 实际账户规则为准。

自建 MQTT + HTTPS 控制台的可选部署见 `deploy/README.md`，本次没有代为开通云服务器或公网域名。

## 测试

```powershell
.\tools\test-firmware.ps1
cd platform
npm test
npm run build
npm run test:browser
```

- 固件主机测试直接编译实际 `pv_app.c` 和 `pv_io.c`，检查业务保护、串口引脚/时钟/中断、三路遥测与同路 ACK、分帧恢复及 Flash 记录 CRC。
- SHT20 驱动主机测试编译实际 `pv_sensors.c`，覆盖无应答、CRC、断连恢复、超时、负温、过期与计时回绕。
- Node 测试检查鉴权、离线/超时、设备回执、串口分帧及本地 MQTT 网关/云端双向链路。
- 浏览器测试使用已有 Edge，无需安装另一个浏览器；模拟数据明确标识且与真实数据隔离。
- 浏览器截图输出到 `platform/test-results`；已覆盖手机、平板与桌面尺寸、断网锁定、图表像素与资源加载。
- 实机联调仍需手动烧录、选择串口并验证传感器接线和标定；真实云服务需要提供部署配置。
